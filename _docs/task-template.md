# Task template

Every groomed GitHub issue has these four sections. Title format: `[Area] Short imperative summary`.

## Summary

One or two sentences: what changes for the user and why. Link the relevant part of `_docs/spec.md` or `openapi.yaml`.

## Acceptance criteria

A checklist. Each item is something a reviewer can look at the result and answer yes or no.

- [ ] Given <state>, when <action>, then <visible outcome>
- [ ] Edge case: <input or state the filer did not mention> results in <outcome>

## Out of scope

What this task deliberately does not do. Every item links to a follow-up issue (`- Thing, see #123`).

## References

Files, docs, endpoints and related issues an engineer needs, for example `_docs/spec.md#phasing`, `backend/app/routers/ranking.py`.
