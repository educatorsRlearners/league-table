# Testing

Every automated suite and the command that runs it.

- **Everything:** `make test-all` is the single command for every automated suite. It runs, in order, `make test`, `make test-frontend`, `make check-ports`, `make test-integration`, and `make e2e`, and stops at the first failure. It needs Docker running and Node installed (the first three steps do not need Docker; only `make test-frontend` and the e2e step need Node). Expect about 1 minute (the first three steps take a few seconds) with images already built; the first run is slower while images build and `npm install` runs. `make check` is the fast, Docker-free subset CI runs (it needs Node for the frontend tests).
- **Before you push:** `make check` runs lint, the backend tests, the frontend tests, and the compose port guard (`make lint`, `make test`, `make test-frontend`, `make check-ports`), stopping at the first failure. CI runs the same `make check` steps on every pull request and on every push to `main`.
- **Backend:** `make test` runs the pytest suite, covering every endpoint, the scoring and adjustment rules, privacy scoping, the risk engine and digest, notes, the seeded edge cases, and the OpenAPI contract.
- **Lint:** `make lint` runs ruff and mypy over the backend (both are dev dependencies).
- **Frontend:** the scoring, risk, and mock-client tests run headlessly under Node with `make test-frontend` (no install step; it prints each failing test and exits non-zero if any fail). The same suites also run in the browser at <http://localhost:8000/Tests.dc.html> while the app is running. CI runs them as part of `make check`. These exercise the reference `scoring.js`/`risk.js`/`api.js` logic, not `httpApi.js`; the shipped page's real HTTP integration is covered by the backend's own endpoint tests plus manual/browser verification.
- **End to end:** `make e2e` drives the shipped page in a real browser against the docker-compose stack (Postgres included). The specs in `e2e/tests/` cover the commitment approval workflow, the instructor's league table (ranking, window and criteria controls, score breakdown, class switching, Present mode), the risk digest and risk record (including that a note never reaches the student), and the student screens, including that the API refuses a student another student's detail. The specs share one database, so assertions avoid exact scores that the approval workflow changes. Shared login helpers are in `e2e/tests/support/auth.js`.
